## 摘要
图表到代码生成要求模型读取图表的细粒度视觉细节，并编写可复现该图表的可执行代码。现有的图表到代码方法要么分别训练视觉和编码能力，要么在图表到代码数据上微调，使两种能力纠缠在一起。这两种策略都没有考虑到两种能力的不同性质，也没有考虑到它们一起优化时产生的干扰。我们提出了MoCA（跨模态仲裁混合体），它将两种能力分开而不是混合。MoCA基于跨模态仲裁块（CAB），该块将视觉分支和代码分支作为两条不同的路径，并有一个轻量级的仲裁器，在每一层和每个生成的令牌上仲裁它们的相对贡献。我们分两个阶段训练MoCA：首先在自蒸馏推理轨迹上进行监督式预热，将视觉理解分解为显式步骤，然后使用对推理过程和最终代码的奖励进行强化学习。分析表明，仲裁器学习到的是结构化而非任意的分配，专家贡献在不同令牌、层和实例上系统性地变化。在三个基准测试中，MoCA取得了与通用领域和图表专用模型相当的竞争性能。消融结果表明，这些收益不能仅归因于更大的模型规模，而是来自互补的视觉和代码分支初始化以及通过CAB进行输入条件仲裁的共同贡献。

## Abstract
Chart-to-code generation requires a model to read the fine-grained visual details of a chart and write executable code that reproduces it. Existing chart-to-code methods either train visual and coding abilities separately, or fine-tune on chart-to-code data with the two abilities entangled. Neither strategy accounts for the distinct nature of the two abilities or the interference that arises when they are optimized together. We propose MoCA (Mixture of Cross-modal Arbitration), which separates the two abilities rather than blending them. MoCA is built on Cross-modal Arbitration Block (CAB), which maintains a visual branch and a code branch as two distinct pathways, and a lightweight arbiter that arbitrates their relative contributions at every layer and generated token. We train MoCA in two stages: a supervised warm-up on self-distilled reasoning trajectories that decomposes visual understanding into explicit steps, followed by reinforcement learning with rewards on both the reasoning process and the final code. Analysis shows that the arbiter learns structured rather than arbitrary allocations, with expert contributions varying systematically across tokens, layers, and instances. Across three benchmarks, MoCA delivers competitive performance against general-domain and chart-specialized models. Ablation results show that the gains cannot be attributed to a larger model size alone, but instead arise from the joint contributions of complementary visual and code branch initialization and input-conditioned arbitration through CAB.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **任务定义**：图表到代码生成（Chart-to-Code Generation）要求模型读取图表的细粒度视觉细节（数据、布局、文本、颜色、样式），并编写可执行的绘图代码以精确复现该图表。
- **核心问题**：视觉理解与代码生成是两种异质能力，且在不同输入和生成阶段其相对重要性是动态变化的。有些图表视觉复杂性高（密集标签、细微颜色、多组件布局），需要更强的视觉感知；另一些则对代码逻辑要求更高（堆叠结构、自定义坐标轴等）。现有方法要么将两种能力分开训练，要么在图表数据上纠缠微调，均未显式建模两者之间的交互与协调，导致优化过程中的相互干扰。
- **现有方法的不足**：
  - 训练型方法（如ChartMaster）通过SFT和RL提升性能，但视觉与代码的交互由模型隐式决定，无法显式控制；
  - 智能体方法（如MatPlotAgent）引入外部反馈迭代优化，但推理开销大；
  - 模型合并方法（如VisCodex）使用全局固定的参数空间系数，对所有输入统一处理，缺乏输入自适应能力。
- **研究意义**：论文首次从"跨模态能力协调"的视角研究图表到代码生成，主张将视觉与代码能力分离并通过显式仲裁机制动态协调，为多模态代码生成提供了新的架构范式。

### 2. 论文提出的方法论

**核心思想**：MoCA（Mixture of Cross-modal Arbitration）采用双分支架构，将视觉理解和代码生成作为两条独立路径，通过一个轻量级仲裁器（Arbiter）在每个Transformer层的每个生成token上动态预测两分支的相对贡献权重。

**关键技术细节**：

- **交叉模态仲裁块（CAB）**：主要由三部分组成：
  - **视觉分支（B_vis）**：从Qwen2.5-VL-7B的FFN参数初始化，保留多模态视觉理解能力；
  - **代码分支（B_code）**：从Qwen2.5-Coder-7B的FFN参数初始化，注入代码合成先验；
  - **仲裁器（Arbiter）**：基于当前隐藏表示计算分支权重，公式为 α = Softmax(W_a·h + b_a)，输出为 α_vis 与 α_code。
- **CAB输出计算**：z = α_vis·B_vis(h) + α_code·B_code(h)，即两分支输出的加权融合。

**两阶段训练框架**：

- **第一阶段：SFT监督微调**——在40万条外部数据（McD数据集）和4.8万条自蒸馏Snippet-of-Thought（SoT）轨迹上进行监督训练。SoT将视觉理解分解为显式的中间推理步骤，提供过程级监督。自蒸馏使得训练轨迹更贴近模型自身的生成分布。
- **第二阶段：GRPO强化学习**——采用组相对策略优化（GRPO），对每个输入生成多个响应，计算五维奖励信号：
  - 格式奖励（R_fmt）：输出格式是否符合要求；
  - 一致性奖励（R_con）：推理轨迹与代码的推理一致性；
  - 结构奖励（R_str）：基于AST分析的关键图表属性重建；
  - 执行奖励（R_exec）：代码能否成功执行；
  - 视觉奖励（R_vis）：渲染图表与参考图像的相似度。

  总奖励 R = R_fmt + R_con + R_str + R_exec + R_vis，兼顾过程级与结果级监督。

### 6. 论文的主要结论与发现

- MoCA在三个基准上取得有竞争力的性能：ChartMimic执行率88.83、Plot2Code Code Pass 87.88、ChartX GPT Score 2.44，均优于或比肩更强更大的基线模型。
- 消融实验表明，MoCA的增益不能归因于模型规模或任务特定训练，而是来自互补分支初始化和输入条件化仲裁的共同贡献。静态参数合并（VisCodex式）效果最差，固定权重次之，验证了"显式仲裁优于隐式融合/静态合并"。
- 仲裁器学习到结构化分配模式：浅层偏重视觉处理，中层代码贡献增加，深层回归视觉精炼；不同token和实例的权重分配存在系统性差异。

- SFT建立稳定的视觉→代码映射，RL进一步在代码可执行性、结构保真度和视觉相似度上带来显著提升（Code Pass 83.33→87.88，Text Match 34.11→41.07，GPT-4o Score 3.66→4.45）。

### 7. 优点

- **概念创新**：首次将图表到代码生成问题形式化为"跨模态能力协调"，将视觉与代码能力显式解耦并建模其交互，视角新颖。
- **架构设计巧妙**：CAB在保留两个专家分支独立性的同时引入极轻量仲裁器，不显著增加参数量和推理开销；将视觉与代码分支初始化为来自不同专长模型，具备可解释性。
- **训练框架完备**：两阶段训练同时覆盖过程级（SoT推理轨迹）和结果级（执行与视觉奖励）监督，奖励设计多维且互补。
- **实验验证扎实**：消融设计系统，逐步剥离训练、初始化、仲裁等变量，证据链完整；仲裁行为可视化分析提供了模型可解释性证据。
- **工程实现细致**：针对双分支架构实现定制kernel并与vLLM集成，考虑了实际部署效率。

### 8. 不足与局限

- **模型规模有限**：只在7B级模型上验证，未探索更大规模（如32B/72B）下双分支架构是否依然有效，结论的泛化性有待验证。
- **算力消耗较大**：RL阶段需要32块H200且每提示生成8个响应，训练成本较高，可能限制实际应用。
- **训练数据依赖**：依赖McD和ChartCoder数据集的规模与质量，自蒸馏依赖教师模型的SoT质量，对无此资源的场景可能不适用。
- **可视化分析局限性**：实例级分析仅展示一对样本，论文也承认这是"示例性"而非全面度量，对输入适应性的证明相对薄弱。
- **评估范围有限**：仅聚焦图表领域，未验证方法在网页UI转代码、文档转代码等其他多模态代码生成场景的适用性。
- **奖励设计的粒度**：视觉奖励依赖GPT-4o自动评估，可能与人类判断存在偏差；五个奖励的权重和形式的敏感性分析不充分。
