## 摘要
迭代式检索-推理智能体近期在多模态长文档问答中展现出潜力。然而，现有系统大多维护一个不断增长的单一上下文，混合了检索痕迹、观察结果和中间推理。随着交互的累积，关键证据变得分散和稀释，使得多跳推理充满噪声。我们提出MARDoc，一种记忆感知精炼智能体框架，将长文档问答解耦为三个专用智能体：用于多粒度多模态检索的探索者（Explorer）、用于将交互痕迹蒸馏为结构化证据和推理记忆的精炼者（Refiner）、以及用于检查证据充分性并提供针对性反馈的反思者（Reflector）。在多次迭代中，智能体依赖动态更新的结构化记忆，而非完整的累积交互历史。这种设计减少了上下文噪声，同时保留了答案关键事实及其逻辑依赖。在MMLongBench-Doc和DocBench上的实验表明，MARDoc取得了强劲结果，超越了同骨干基线，并证明了结构化记忆对于智能体文档问答的有效性。

## Abstract
Iterative retrieval-reasoning agents have recently shown promise for multimodal long-document question answering. However, most existing systems maintain a single growing context that mixes retrieval traces, observations, and intermediate reasoning. As interactions accumulate, key evidence becomes scattered and diluted, making multi-hop reasoning noisy. We propose MARDoc, a Memory-Aware Refinement Agent framework that decouples long-document QA into three specialized agents: an Explorer for multi-granularity multimodal retrieval, a Refiner for distilling interaction traces into structured evidence and reasoning memories, and a Reflector for checking evidence sufficiency and providing targeted feedback. Across iterations, the agents rely on a dynamically updated structured memory rather than a full accumulated interaction history. This design reduces context noise while preserving answer-critical facts and their logical dependencies. Experiments on MMLongBench-Doc and DocBench show that MARDoc achieves strong results, outperforming same-backbone baselines and demonstrating the effectiveness of structured memory for agentic document QA.

- **研究问题**：多模态长文档问答（multimodal long-document QA）面临两大挑战：（1）信息以文本、布局、表格、图形等多种模态共同表达，模型需要跨模态对齐与推理；（2）支持证据通常稀疏分布在多页文档中，难以定位、关联和综合，尤其是在长上下文中进行多跳推理。
- **现有方法的不足**：
  - 早期OCR-based端到端模型难以扩展到超长文档（上下文长度限制）。
  - 检索增强生成（RAG）方法虽减少输入长度，但跨页面和跨模态的证据仍然难以关联，限制多跳推理。
  - 近期基于智能体（agent）的方法引入规划、工具调用、迭代检索，但普遍采用“单一增长上下文流”范式：每次交互将新检索结果和中间推理追加到一个不断增长的单一上下文中，导致关键证据因历史噪声而稀释，且缺乏基于记忆的质量控制机制，早期错误可能累积并放大。
- **论文核心含义**：提出一种记忆感知精炼智能体框架MARDoc，通过将检索、证据提炼和反思解耦为三个专门智能体，并采用动态更新的结构化记忆代替完整交互历史，从根本上缓解上下文稀释问题，提升多跳推理的准确性和鲁棒性。

## 2. 方法论：核心思想、关键技术细节

### 2.1 整体框架

MARDoc围绕“Explorer（探索者）–Refiner（精炼者）–Reflector（反思者）”循环构建，分为四个关键组件：
1. **文档结构构建模块**：使用MinerU2.5解析文档得到细粒度语义节点（保留布局结构），并利用Qwen3-VL（或类似MLLM）为视觉元素生成描述，构建统一索引（outline）。
2. **Explorer（探索者）**：基于ReAct框架，接收查询Q、结构化大纲O、当前记忆M_{t-1}和反思指令R_{t-1}，使用多粒度工具集（文本/视觉模态，如搜索关键词、获取段落、获取页面图片、获取表图像、搜索元数据等）迭代检索证据，并产生推理链T_t及候选答案。
3. **Refiner（精炼者）**：模拟人类专家解决复杂问题的认知过程——不记忆所有细节，而是形成清晰的思维线索，记录关键信息、核心证据及其逻辑关系。在每轮探索结束后，Refiner将当前推理链T_t与上一轮记忆M_{t-1}整合，生成两种结构记忆：
   - 证据记忆（Evidence Memory, M_E）：记录与查询最相关的事实信息及其来源，去除冗余噪声。
   - 推理记忆（Reasoning Memory, M_R）：提取清晰的推理路径，将证据节点链接成证据链，并标注依赖关系。
   结构记忆M_t = (M_E, M_R) 替代原始变化上下文，使得后续智能体可以紧凑地回顾历史信息，避免进入错误的探索路径。
4. **Reflector（反思者）**：在每次精炼之后，检查当前记忆M_t是否足以回答查询Q：
   - 若充分，输出最终答案A；
   - 若不充分或存在错误，生成针对性的反馈指令R_t（例如“缺少某个总数”、“用户询问的是ChatGPT-4o而非BERT”），引导Explorer更有效地检索，避免重复错误。
- **关键创新**：用结构化记忆替代全历史积累，实现了紧凑、可验证的推理状态，解决了上下文稀释和错误累积问题。

### 2.2 迭代算法流程（文字描述）

- 初始化：记忆M_0为空，指令R_0为空。
- 对于每一次迭代 t = 1, 2, ..., K（最大迭代次数设为3，探索阶段工具调用上限10次）：
  1. Explorer根据Q、大纲O、当前记忆M_{t-1}和指令R_{t-1}进行多步检索与推理，生成推理链T_t。
  2. Refiner接收Q、T_t和M_{t-1}，精炼出新的结构化记忆M_t。
  3. Reflector检查M_t，若充分则输出最终答案A；否则输出反馈指令R_t，继续下一次迭代。

## 3. 实验设计

### 3.1 数据集与基准（Benchmark）

- **MMLongBench-Doc**：135份文档，平均47.5页，覆盖7个领域（学术、手册、金融、指南、行业、报告、教程），含1082个问题，其中34%需要跨页面推理。评估指标：Accuracy和F1（使用GPT-4o提取答案，规则计算）。
- **DocBench**：229份真实文档，1102个问题，跨越5个领域和4种问题类型。评估使用官方GPT-4o判别器。

### 3.2 对比方法

论文将基线分为三类：
- **MLLM-based方法**：Vanilla VLM（直接输入所有页面图像）、DocSeeker、Docopilot。
- **RAG-based方法**：SV-RAG、VisRAG、BOOKRAG、MoLoRAG、M3DocRAG、RAGAnything。
- **Agent-based方法**：Doc-React、MDocAgent、MACT、Chain-of-Agent（COA）、SLEUTH、DocAgent、DocDancer。

### 3.3 骨干模型与设置

- 主要骨干：Qwen3-VL-30B-A3B-Instruct 和 Qwen3-VL-8B-Instruct。
- 额外实验使用Qwen3-VL-32B-Instruct。
- 框架基于prompt engineering，无任务特定微调。
- 推理框架：vLLM，温度0.7，top_p 0.8，最大上下文长度128K tokens。

## 4. 资源与算力

- **文中明确说明**：所有实验使用四块NVIDIA A800 GPU（每块80GB显存）。

- **主实验**：在MMLongBench-Doc和DocBench两个基准上对比了3大类共14种以上基线方法，包含相同骨干和不同骨干的对比。

## 6. 主要结论与发现

- MARDoc通过结构化记忆替代单调增长上下文，显著提升了多模态长文档问答的性能。
- 在MMLongBench-Doc上，使用Qwen3-30B达到57.1% Accuracy，与使用Claude 3.5 Sonnet的DocAgent（57.3%）几乎持平，远超同骨干的DocAgent（48.3%）。
- 在DocBench上，MARDoc以82.1的LASJ得分领先所有同骨干方法。
- 证据记忆（M_E）确保事实忠实性，推理记忆（M_R）保证逻辑连贯性；两者结合在减少幻觉和支持多跳推理方面表现优异。
- Refiner和Reflector必须协同工作：仅保留Reflector而无Refiner时性能大幅下降，因为噪声破坏了反思过程。
- 最大迭代次数K=3为最佳；K=4时略有下降，因冗余信息稀释了结构化记忆。
- 细粒度文档表示（MinerU2.5）优于粗粒度表示（DocXChain），对性能有显著贡献。
- 额外计算成本带来了显著的准确率提升，符合测试时扩展范式。

## 7. 优点

- **方法论创新**：提出“探索-精炼-反思”协同工作流，用结构化记忆替代全历史迭代，从根本上解决了长上下文多跳推理中的上下文稀释和错误累积问题。
- **结构清晰**：将检索、证据消化、质量检查解耦为三个职责明确的智能体，每个智能体功能单一、可解释性强。
- **实验充分**：在两个权威基准上进行广泛实验，消融实验深度分析每个组件的作用，并考虑了不同类型问题（单跳/多跳/不可回答）、不同证据页面数、不同骨干模型。
- **公平性**：所有对比均基于相同骨干设置，控制变量，展示了结构化记忆的增益。
- **实际价值**：证明了即使不进行任务微调，通过巧妙的记忆管理和反馈机制也能达到甚至超越闭源大模型的效果，降低了部署成本。

## 8. 不足与局限

- **方法完全基于提示工程（prompt engineering）**：未使用任务特定微调，作者也指出引入训练可能进一步提升性能。
- **骨干模型限制**：目前仅在Qwen3-VL系列上评估，未验证在其他多模态模型（如InternVL、GPT-4V等）上的泛化性。
- **计算开销**：迭代循环涉及多次工具调用和LLM推断，较单次通过方法增加延迟（每样本平均多15.9秒）。作者提到未来可探索早期停止策略以减轻开销。
- **迭代次数固定为3**：对某些简单问题可能过深，对复杂问题可能不足，缺乏自适应调整机制。
- **实验覆盖**：虽然数据集规模不小，但未在更多真实长文档场景（如法律合同、医学报告）上测试，可能存在领域偏差。
- **依赖外部解析工具**：MinerU2.5的解析质量直接影响整体效果，工具错误可能引入偏差。
- **篇幅限制**：附录中提示词未完全详细公开，可能影响复现性（论文中提供了图5-7的prompt模板，但细节可进一步补充）。
