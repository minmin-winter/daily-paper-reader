## 摘要
语言智能体越来越多地部署在积累的多模态信息之上，然而现有基准通常以人-人交互形式呈现，视觉内容稀疏且内容直白，既不评估对真实多模态文件交互的推理，也不评估对隐藏用户信息的解读。因此，我们提出M³Exam，一个基于真实用户-智能体交互的以查询为中心的多模态对话记忆基准，包含跨模态基础推理和隐含信息推断的多维度评估。对多模态大语言模型和记忆系统的基准测试揭示了在跨模态基础推理、跨会话推理以及积累多模态上下文的效率成本方面持续存在的差距。我们进一步提出M³Proctor，一种多模态记忆方法，它检测查询模态偏好，仅按需消耗原始视觉资源，将准确率提升13%，同时将索引构建时间和检索令牌数减少超过70%。

## Abstract
Language agents are increasingly deployed over accumulating multimodal information, yet existing benchmarks assume a human-human form with sparse visuals and straightforward content, evaluating neither reasoning over authentic multimodal file interaction nor the interpretation of concealed user information. We therefore introduce M$^3$Exam, a query-centric multimodal conversational memory benchmark built on realistic user-agent interaction, with multi-dimensional evaluation spanning cross-modal grounding and implicit information inference. Benchmarking MLLMs and memory systems reveals persistent gaps in cross-modal grounding, cross session reasoning, and the efficiency cost of accumulating multimodal context. We further propose M$^3$Proctor, a multimodal memory method that detects query modality bias and consumes raw visual sources only on demand, improving accuracy by 13% while cutting index-construction time and retrieved tokens by over 70%.

## 2. 方法论：核心思想、关键技术细节、算法流程
### 2.1 M³Exam 基准构建
- **任务形式**：给定一个由多会话对话 D = (D1, D2, ..., DL) 和查询 x 构成的实例，智能体需从历史 H 中检索正确证据，跨文本、图像、文档进行基础推理，并解释隐含信息。
- **构建管道**（图2）：
  1. **源输入**：每个实例基于三元组 (Persona, Core Event, Multimodal File Pool) 合成。Persona 定义用户身份；Core Event 是叙事主线；File Pool 包含图表、照片、PDF 文档。
  2. **时间线构建**：利用文本 LLM 生成核心事件线（N 个事件），包含描述、视觉查询、日期、搜索关键词；同时生成 M 个干扰侧事件（与核心事件正交）并混合。
  3. **多轮对话合成**：采用事件滑动窗口机制，每一步模拟用户-助手交互。用户模拟器基于当前事件和历史摘要生成查询；助手基于上下文和附加图像回复；每轮产生摘要添加到运行记忆。
  4. **问题库合成**：从最终对话中合成8种类型的问题（覆盖记忆、推理、解释三大能力），每种类型对应不同难度和证据跨度。
- **质量控制**：每个阶段都经过 LLM 自检和人工检查，确保人物一致性、事件连贯性、问题可回答性。

### 2.2 M³Proctor 方法
- **核心思想**：检测查询的模态偏差（即查询对图像、文档、图表的依赖），仅按需消耗原始视觉资源，避免盲目注入所有视觉信息导致的性能下降和成本爆炸。
- **关键模块**：
  1. **多模态索引构建**：将每轮对话中的模态（图像、文档、图表）投影为文本替代物（如图像字幕、图表数字转录、文档摘要），并附加模态标签 ⊮ₘ(c)。同时附加紧凑的会话摘要块，以保持跨会话信号。
  2. **模态感知推理**：
     - **偏置检测**：通过一次 LLM 调用获取查询的模态偏好向量 b(q) ∈ {0,1}^|M|，指示查询是否需要各模态。
     - **偏置感知重排序**：在基于稠密检索的候选池中，用 b(q) 和每个候选块的模态标签 ⊮ₘ(c) 计算修正分数 s(q,c) = cos(q,c) + ∑λₘ·bₘ(q)·⊮ₘ(c)，保留 top-k 块。额外引入多样性约束以覆盖多会话。
     - **代价感知级联**：第一阶段用文本替代物回答问题，若置信度低（不可靠或模态偏置未满足），则第二阶段按需注入原始视觉源。级联条件为 Φ(â₁,q) = 1 当 u(â₁)=1 或 β(q)=1。第二阶段由融合模态证据分数 eₘ(q) 驱动，仅当分数超过阈值时使用原始源。
- **优势**：大部分查询（约 73.6%）在文本阶段终止，避免视觉计算开销；准确率提升 13%，索引构建时间减少 70%，检索 token 减少 70% 以上。

## 3. 实验设计
### 3.1 数据集 / 场景
- **M³Exam 基准本身**：包含239个多会话对话，涵盖15种人物画像（如兽医、咖啡师、飞行员、学生等），总计 3,025 轮用户-助手交互，附带 1,799 个多模态工件（图像、PDF），以及 5,150 个评估问题。问题分为8种类型：单会话（SS）、多会话（MS）、时间推理（TR）、多模态推理（MR）、文件管理（FM）、事实判断（FJ）、主题推理（TH）、隐式推断（II）。其中 34.9% 为跨模态，14.9% 需要解释。

### 3.2 对比方法

### 3.3 评估指标
- **Exact Match (EM)**：对短答案使用分级匹配（描述答案列表中的不同精确度）。
- **Token-level F1**：基于 SQuAD 样式。

- **Overall Score**：0.5*LLM-J + 0.5*mean(EM, F1, BLEU-1)。特殊类型（FM, FJ）有专门的 EM 规则。

## 6. 主要结论与发现
1. **M³Exam 极具挑战性**：最强前沿 MLLM（GLM-5.1）仅达 0.549 综合分数，记忆系统普遍低于 0.5。
2. **瓶颈在于跨模态和隐式意图问题**：模型在单会话推理上表现尚可，但在 MR（多模态推理）、FM（文件管理）、TH（主题推理）、II（隐式推断）上严重下降。这表明根本障碍是跨模态基础推理和隐式上下文解读，而非模型能力上限。
3. **M³Proctor 提升了记忆系统前沿**：在 7B 骨干上达到最佳综合分数 0.484，在 MR（0.606）、II（0.652）、FM（0.569）上领先所有记忆系统，甚至超过一些前沿 MLLM。
4. **级联策略高效**：级联仅在真正需要视觉源的查询（如 FM 68%、MR 51.1%）上启动，文本型查询（<15%）免于视觉开销，整体实现多模态准确率与文本级成本。
5. **现有多模态记忆系统效率低下**：盲目注入所有视觉资源导致索引构建时间（MIRIX 43,271 秒）和 token 消耗（NGM 26,988 tokens）极高。

## 7. 优点
- **基准创新性**：首个同时包含跨模态记忆、推理、解释三种能力的基准，8 种问题类型覆盖全面，15 个人物画像和 239 个多会话场景提供了丰富多样性。
- **方法论亮点**：
  - M³Proctor 将模态偏置作为一等信号，实现按需视觉消费，而非统一处理，这显著降低了成本且保持了高准确率。
  - 偏置检测和级联策略均基于轻量 LLM 调用（偏置检测只一次），避免了每步做多模态前向传递的高开销。
  - 多样约束（覆盖多会话、多模态）确保重排序结果适合多会话推理。
- **实验严谨性**：
  - 多种骨干验证排除了单模型偏差。
  - 消融和分析深入（级联启动率、多模态提升、效率对比）。
  - 指标多维且经过人工验证一致性。

## 8. 不足与局限
- **实验覆盖方面**：
  - 当前基准仅支持单轮查询评估，缺乏长程多轮交互中的动态意图更新和迭代记忆更新的评估。论文在限制中承认了这一点，并计划扩展。
  - 所有数据使用合成对话，可能缺乏真实用户对话的噪声、口语化、不一致性等特征。
- **方法局限**：
  - M³Proctor 在解释导向问题（尤其是隐式推断 II）上性能仍有限，仅 0.652 LLM-J，表明对隐含用户状态的建模不足。
  - 偏置检测依赖单一 LLM 调用，对于复杂或模糊的查询可能误判。
  - 级联的代价模型基于硬阈值，可能不够自适应。
- **应用限制**：
  - 当前基准和方法的评估集中在学术界模型，对生产级系统（如处理数十万会话）的扩展性未探讨。
  - 基准的 15 个人物画像可能无法覆盖所有现实领域的多样性（如金融、医疗等专业场景未专门设计）。
- **资源与公平性**：论文未提供详细训练时间（因为无需训练），但索引构建时间在不同系统间差异大（如 MIRIX 需 43,271 秒 vs M³Proctor 72 秒），公平比较需考虑实际部署条件。
