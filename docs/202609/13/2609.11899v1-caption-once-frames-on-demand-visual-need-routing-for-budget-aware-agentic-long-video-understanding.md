## 摘要
边缘设备上的长视频理解必须在严格的计算与带宽预算下对长达数小时的内容进行推理。对视觉 token 进行下采样会丢失时间结构，而纯文本的视频记忆则会丢失细粒度的视觉属性。我们观察到一种视觉—文本二元性：语言记忆比密集帧更能承载长程时间结构，而像素对于属性级感知仍然具有决定性作用。基于这一洞见，我们提出 Caption-once, Frames-on-Demand（CFD），一种预算感知的边缘—云智能体框架。边缘端执行一次离线描述生成，构建双轨叙事索引，即事件级故事骨架加上片段级微日志；该索引被缓存并在各查询间复用，无需重新生成描述。在查询时，云端 MLLM 在一个以故事为先的循环中基于该索引进行推理，其核心是一个轻量级视觉需求路由器（Visual-Need Router）：该逐查询门控模块仅对感知类问题（外观、屏幕文字、属性消歧）触发有界的关键帧检索，并将时间—结构类问题保留在语言空间中。该路由器将视觉访问转化为一种一等公民的、以查询为条件的成本，无论视频长度如何，都限制每次查询的帧消耗量。在长视频基准上的实验展示了强劲的精度—效率权衡，同时大幅减少在线视觉处理。

## Abstract
Long-video understanding on edge devices must reason over hours of content under tight compute and bandwidth budgets. Subsampling visual tokens loses temporal structure, while text-only video memories lose fine-grained visual attributes. We observe a visual-textual duality: language memories carry long-range temporal structure better than dense frames, while pixels remain decisive for attribute-level perception. Building on this insight, we propose Caption-once, Frames-onDemand (CFD), a budget-aware edge-cloud agentic framework. The edge runs a single offline captioning pass that builds a dual-track narrative index, an event-level story skeleton plus a clip-level micro-log, cached and reused across queries without re-captioning. At query time, a cloud-side MLLM reasons over the index in a story-first loop centered on a lightweight Visual-Need Router: a per-query gating module that triggers bounded keyframe retrieval only for perceptual questions (appearance, on-screen text, attribute disambiguation) and keeps temporal-structural questions in language space. The router turns visual access into a first-class, query-conditioned cost, capping per-query frame consumption regardless of video length. Experiments on long-video benchmarks demonstrate strong accuracy-efficiency trade-offs while substantially reducing online visual processing.

# 论文总结：Caption-once, Frames-on-Demand (CFD)

## 1. 核心问题与研究动机

- **背景**：长视频理解（数小时级内容）在边缘设备与延迟敏感的云服务中面临严格算力与带宽预算。系统需在整个视频时间跨度上保留与查询相关的记忆，但漏掉一个决定性的小事件或属性就会直接导致回答错误。
- **现有方法的两条设计轴线及其缺陷**：
  - **视觉压缩方法**（减少采样帧数或压缩视觉 token）：降低开销，但在长视频上牺牲覆盖度与保真度。
  - **文本翻译方法**（转为字幕/转录/语言记忆，或迭代回访视频段更新文本记忆）：提升可扩展性，但纯文本表示会丢失细粒度视觉证据；迭代回访还引入随交互轮数增长、难以在边缘预算下约束的查询时开销。
- **关键观察——视觉—文本二元性**：
  - 图像级指代任务中，仅凭字幕推理弱于原始像素推理（细粒度身份、颜色、属性绑定在语言压缩中易丢失）。
  - 长程时序推理中，语言记忆有时**优于**密集视觉输入（提供紧凑、离散的事件顺序记录）。
  - 结论：文本并非视频的有损替代品，而是时序结构的更强载体；稀疏原始帧仍是可验证视觉证据的必需。
- **核心命题**：效率不来自均匀削减视觉计算，而来自**将视觉访问选择性地分配给属性关键的时刻**。

## 2. 方法论

### 2.1 核心思想：Caption-once, Frames-on-Demand (CFD)

- 边缘端一次离线描述生成（question-agnostic），构建**双轨叙事索引**并缓存复用，跨查询不再重新描述。
- 云端 MLLM 以**故事优先（story-first）**循环推理，仅当语言不足时才按需检索有界关键帧。
- 视觉访问被转化为**一等公民的、以查询为条件的成本**，与视频长度无关地限制每查询帧消耗。

### 2.2 三层边缘—云记忆架构

- **Tier 1 事件记忆（全局故事骨架）**：
  - 用镜头边界检测器（TransNetV2）将视频切分为语义连贯事件，短于阈值 τ_min 的相邻段合并到前一段，得到变长事件 {e₁,…,e_K}。
  - 轻量描述 MLLM 按事件级提示词生成结构化叙事画像 m^E_k = Captioner(e_k, p_event)，包含场景概览、实体列表、时序事件流、检索锚点标签。
  - 完整事件记忆 M_E 始终全量呈现给推理智能体，作为全局时间线与所有问答的起点。
- **Tier 2 片段记忆（局部时序细节）**：
  - 独立于事件分割，将视频按固定时长 τ_c（可配置步长）切为片段 {c₁,…,c_L}，用微动作级提示词生成 m^C_j = Captioner(c_j, p_clip)，一句一个动作。
  - **不整体注入**推理智能体：仅当循环定位到事件 e* 时，将时间区间与之重叠的所有片段描述作为嵌套子描述注入 e*。
  - 注入是**累积的**（累积到富集库 B），一旦注入便在同一查询的后续推理步骤中持续存在；以纯文本操作组合已缓存字幕，**零额外视觉成本**，替代了此前工作中的在线重描述。
- **Tier 3 视觉工作记忆（像素级证据）**：
  - FIFO 队列 W，固定小容量 N_wm，存放从视频中提取的原始帧。
  - 容量比视频总帧数小若干数量级（如 1 小时视频仅 16 帧），既防止视觉 token 稀释 LLM 注意力，又最小化边缘到云的上行带宽与能耗。
  - 三层构成由粗到细的递进：事件记忆提供广度，片段记忆在目标时间段增加深度，视觉工作记忆在语言不足时提供像素级证据；三者联合置于单一多模态提示词中。

### 2.3 四个智能体角色（均通过提示词工程实例化）

- **Captioning Agent（仅离线）**：边缘侧 MLLM，按式(1)(2)处理每个事件与均匀片段；缓存后不再对同一视频的后续查询调用。
- **Answering Agent**：给定叙事记忆 M 与视觉工作记忆 W，输出 (a, conf, r) = ANS_AGENT(M, W, Q)，其中 a 为候选答案、conf 为置信标志、r 为思维链理由；文本记忆与视觉证据（帧与其时间戳交错）组装为单一多模态提示词。conf=true 时返回答案，否则进入/继续推理循环。
- **Localization Agent**：从 M_E \ S_tried 中选出单个最相关事件 e* = LOC_AGENT(M_E \ S_tried, W, Q)，S_tried 为本次查询已访问事件集合，保证每次迭代探索新的时间区域。
- **Visual-Need Router（CFD 独有）**：need_visual = ROUTER(e*, Q, r)，按"感知 vs 时序"准则判断像素级检查是否可能提升正确性：
  - **接受（触发取帧）**：问题针对外观、屏幕文字、空间布局、物体消歧等无法仅凭文本可靠推断的证据。
  - **拒绝（跳过取帧）**：问题主要涉及时序排序、场景转换、长程叙事结构，此时清空 W 并直接进入下一轮迭代，不产生任何视觉成本。
  - 论文明确指出：路由器是**显式的成本控制门**，可能牺牲属性类问题的边际精度以换取大幅降低的平均视觉足迹，这是刻意设计的特性而非缺陷；优先属性保真的应用可直接禁用路由器、始终取帧。
- **关键差异**：CFD 完全取消了此前流水线中的 **Instruction Agent**（用于分析缺失信息并生成重描述指令，会在查询时触发额外 VLM 调用），代之以预计算的片段记忆 + 视觉需求路由器两个互补机制。

### 2.4 故事优先推理循环（算法流程，最大迭代预算 T）

- **初始化**：W = ∅，S_tried = ∅，富集库 B = ∅。
- **Step 1 故事优先回答**：Answering Agent 仅凭完整事件记忆 M_E 与空 W 尝试回答；若置信则立即返回。此早期退出处理仅凭故事骨架即可解决的时间与叙事类问题，整次查询只需一次 LLM 调用。
- **Step 2 时序定位**：Localization Agent 从 M_E \ S_tried 选出最相关事件 e*，并将其加入 S_tried。
- **Step 3 片段富集后重答**：收集与 e* 时间重叠的所有片段记忆条目，作为嵌套子描述注入 e* 的事件字幕，并累积进 B；重建叙事记忆（每个事件先恢复基础事件文本以防嵌套累积，再按时间顺序在"More details"块下追加其片段字幕）。Answering Agent 用富集后的记忆重试；若置信则返回。由于 B 跨迭代累积，叙事随探索事件增多而渐进丰富。
- **Step 4 视觉需求路由**：若仍不置信，路由器按式(5)判断是否需对 e* 做像素级检查；若拒绝，清空 W 并回到 Step 2 进入下一轮。
- **Step 5 按需取帧**：路由器接受时，从 e* 自适应采样关键帧，采样率 f_ev 且每事件封顶 N_fr 帧；超过上限时在事件时长内均匀重分配。帧被推入容量为 N_wm 的 FIFO 工作记忆。
- **Step 6 多模态重答**：Answering Agent 在单一多模态提示词中同时接收富集叙事记忆（含全部累积片段注入）与 W 中的视觉证据；若置信则返回。
- **Fallback**：若 T 轮迭代耗尽仍无置信答案，强制用所有累积的文本与视觉证据提交最佳答案。
- **循环特性**：每轮迭代使系统对视频的记忆渐进丰富——探索新事件（广度）、永久注入片段细节（深度）、在 W 中累积视觉证据（接地）。
