## 摘要
虽然统一多模态模型（UMMs）在单一模型中联合执行视觉理解与生成，但功能上的统一并不能保证学习上的协同：这两个目标可能相互促进、争夺容量，或仅仅共存。我们在无预训练视觉先验的可控、结构原生设置中，从表征、任务和系统层面研究它们的关系。在表征层面，我们发现每个目标都为另一个目标提供有用信号：生成丰富了用于理解的视觉特征，而理解则加强了用于生成的视觉-语言对齐。然而，当两个目标被迫通过同一计算路径时，往往会出现一方主导的情况。一种任务解耦架构，在保持语义交互的同时专门化冲突的视觉计算，可避免这种不对称退化。在任务层面，通过三个案例研究，我们发现当理解与生成任务依赖共享知识时，存在正向的双向迁移。在系统层面，我们展示了在明确需要图像理解与生成的复杂任务上，端到端UMM优于匹配的规划器-执行器流水线。这些结果共同表明，UMM的价值不仅限于统一接口：适当专门化、共享任务知识和端到端优化可将共存转化为协同。

## Abstract
While unified multimodal models (UMMs) jointly perform visual understanding and generation within a single model, functional unification does not guarantee learning synergy: the two objectives may reinforce each other, compete for capacity, or merely coexist. We investigate their relationship at the representation, task, and system levels in a controlled, structurally native setting without pretrained vision priors. At the representation level, we find that each objective provides useful signal to the other: generation enriches the visual features learned for understanding, while understanding strengthens vision--language alignment for generation. However, when both objectives are forced through the same computation path, one tends to dominate. A task-decoupled architecture that specializes conflicting visual computation while preserving semantic interaction avoids this asymmetric degradation. At the task level, through three case studies, we find positive bidirectional transfer when understanding and generation tasks rely on shared knowledge. At the system level, we show that an end-to-end UMM outperforms a matched planner--executor pipeline on complex tasks that explicitly require both image understanding and generation. Together, these results show that the value of UMMs extends beyond a unified interface: appropriate specialization, shared task knowledge, and end-to-end optimization can turn coexistence into synergy.

## 1. 论文的核心问题与整体含义

本文聚焦统一多模态模型（UMMs）中的一个基础性问题：**视觉理解与视觉生成在同一模型内联合学习时，二者之间究竟会发生什么**——是互相促进、相互干扰，还是仅仅共存？尽管已有许多 UMMs 在功能上同时支持理解与生成，但“功能统一”并不等于“学习协同”，两项目标可能在共享表征中互相增强、争夺容量、或互不相关地共存。现有研究对“统一是利是弊”结论不一，且多依赖外部视觉编码器或 VAE，难以干净地隔离理解与生成之间的内在关系。

为厘清机制，作者在**无预训练视觉先验的“原生”像素级结构设置**下开展控制变量研究，系统考察统一模型的真实收益与条件。其核心含义是：UMMs 的价值是否有条件地取决于**架构设计、任务知识和优化方式**，而非仅仅是一个“统一接口”。

## 2. 论文提出的方法论

### 2.1 总体框架

文章设计了一种“像素进、像素出”的原生多模态建模方式，结合**自回归文本建模 + 流匹配（flow matching）图像生成**的混合范式。所有视觉输入/输出均直接以像素 patch 进入模型，不使用预训练视觉编码器或图像 tokenizer / VAE，从而排除外部视觉先验对因果推断的干扰。模型以 Qwen3-1.7B 为语言基础，并增加随机初始化的“pre-buffer”层，图像 patch 经卷积层映射后进入 LLM 解码层，序列内文本与图像 token 按任务进行位置编码。

### 2.2 三种受控路由架构

为隔离“参数共享”与“任务竞争”，作者比较了三种架构：

- **Dense Sharing（密集共享）**：文本、理解用清晰视觉 token、生成用噪声视觉 token 全部经过同一 LLM 层，最大化参数共享。
- **Modality-decoupled MoT（模态解耦）**：文本保留在预训练语言分支；**所有**视觉 token（理解与生成）被路由到新初始化的视觉分支，模拟 Mixture-of-Transformers 设计。
- **Task-decoupled MoT（任务解耦）**：理解用视觉 token 留在语言分支，生成用噪声视觉 token 走专门化生成分支；两分支通过共享文本上下文注意力以及图像编辑/重建任务实现软对齐，并额外加入 20% 图像重建数据。

通过对比这三类路由，作者试图分离“计算路径共享”与“语义交互”各自的作用。

### 2.3 表征、任务与系统三层面分析策略

- **表征层面**：对视觉特征做线性探测（图像分类、语义分割、深度估计）、PCA 可视化、CKA 文图对齐分析，判断理解/生成联合训练对表示的影响。
- **任务层面**：选择三个可能共享知识的领域——几何推理、SVG 矢量图、3D 空间智能。通过“单任务训练 vs 联合训练”验证双向迁移；并用“将生成数据改写为理解任务（Textual-Desc）”作对照，排除单纯“更多数据”带来的增益。
- **系统层面**：对比端到端 UMM 与“规划器（理解）→执行器（生成）”流水线。将同一批推理编辑数据分别格式化为端到端样本、规划样本和执行样本，训练三种模型后再配对组成系统，实现受控比较。

## 6. 论文的主要结论与发现

1. **表征层面（Finding 1）**：理解与生成可以在表征上互相提供信号——生成监督使理解所用视觉特征更丰富（探测准确率更高、PCA 特征区域更一致），理解监督改善生成过程中文-图语义对齐（CKA 更高）。但在“同一计算路径”的密集共享模型中，预训练 LLM 会使理解主导、生成退化；在模态解耦模型中则相反，生成主导、理解退化。**任务解耦架构**——把理解视觉 token 留在语言侧、生成视觉 token 放进专门分支，同时保留语义交互——能实现两方向共同提升，而不产生不对称退化。

2. **任务层面（Finding 2）**：当理解与生成任务依赖共享领域知识或共同底层能力时，单向训练的正信号可以双向迁移。几何推理（生成几何图 → 提升解题与通用数学推理）、SVG（代码↔图像相互促进，联合训练显著提高“从 SVG 代码心智重建图像”的能力）、3D 空间智能（理解与生成在 9 个空间理解基准及多个生成任务上均获得提升）均验证了这一规律。特别地，去掉“生成”后仅保留相同数据对应的文本描述，增益变小，说明生成目标本身贡献了不可替代的约束信号。

3. **系统层面（Finding 3）**：在需要理解、推理、生成紧密耦合的复杂任务（推理型图像编辑）上，端到端联合学习一个 UMM 优于将理解模型和生成模型以“规划器→执行器”形式按顺序拼接的模块化 pipeline，且两套系统使用相同基座与数据监督。

综合来看：**统一多模态模型的增益不是无条件的**；只有合适的计算专业化、共享任务知识、端到端优化三者结合，才能将“共存”转化为“协同”。

## 7. 优点

- **受控性强的实验设计**：避开外部视觉编码器和 VAE，在“无外部视觉先验”的原生像素环境中隔离理解与生成的交互，显著提升因果推断的干净度。
- **三层级的系统性视角**：从表示层到任务层再到系统层，层层递进，比单一 benchmark 对比更能揭示 UMMs 中协同/冲突的本质。
- **主动设计并检验了解决路径**：不仅指出冲突，还提出了 Task-decoupled MoT 并通过实验支持其有效性；其“软对齐”机制具有一定设计与迁移价值。
- **精细的对照组**：如将同名生成数据转成理解任务（Textual-Desc），能清楚区分“生成目标本身”与“更多数据”的贡献，控制严谨。
- **多域任务案例选择**：几何、SVG、3D 空间智能跨度大，且均设计了针对性的诊断（如 SVG Blind VQA、早期去噪可视化），支撑结论的一般性。
- **系统级比较具有匹配性好**：端到端与 planner-executor 共用同一初始化、同一批推理编辑数据，使系统层面的比较更公平。

## 8. 不足与局限

- **建模范式单一**：论文只验证“自回归文本 + 流匹配图像”这一当前主流混合范式，未在全离散 token 或全自回归、离散去噪等其他统一化范式下验证结论泛化性。
- **架构探索受限**：Task-decoupled MoT 是一种可行方案，但作者并未系统搜索最优的“共享 vs 专门化”平衡点；MoE、任务相关路由等替代架构未覆盖。
- **规模与初始条件现实约束**：模型从预训练 Qwen3-1.7B 出发，不是完全“原生从头训练”，语言先验可能影响理解与生成的竞争模式；更大参数规模下两者关系是否会变化尚不清楚。
- **系统层面任务单一**：只研究了推理编辑场景，缺少多模态搜索+生成、智能体交互、动态世界建模等更复杂任务来进一步证明“端到端统一优于流水线”的普适性。
- **资源信息缺失**：未报告 GPU 数量、训练时长、硬件成本，影响可复现性与实践判断。
